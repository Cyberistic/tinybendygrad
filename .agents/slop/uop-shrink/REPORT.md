## WHAT WAS DONE

### 1. THE `op`+`nsrc` PREFIX, ONCE, FOR EVERY RULE THAT USES IT  (-41 lines)

**THE MEASUREMENT.** MEASURED 2026-11-10, THIS FILE HAS **109** `sym_*.pat` DEFS (THE
PORT's ANSWER TO UPSTREAM's `UPat(...)`) AND **43** OF THEM HAVE THE **EXACT** BODY

```
Bool.and(Bool.and(sy_is_op(x, u, OP), sy_nsrc_is(x, u, N)), REST)
```

-- 39 WITH `is` AND 4 WITH `ge` -- SPANNING **202 LINES**. `sym_*.pat` IS WHERE THE
HAND-EXPANSION SPENT ITS LINES, AND THE PREFIX IS THE PART THAT IS **THE SAME FOR EVERY
RULE**.

**THE FIX.** TWO HELPERS, `sy_pat_is` AND `sy_pat_ge`, AND 43 CALL SITES.

```
def sy_pat_is(+x: F.Folded, +u: U32, want: O.Op, n: U32, rest: Bool) -> Bool:
  Bool.and(Bool.and(sy_is_op(x, u, want), sy_nsrc_is(x, u, n)), rest)

def sy_pat_ge(+x: F.Folded, +u: U32, want: O.Op, n: U32, rest: Bool) -> Bool:
  Bool.and(Bool.and(sy_is_op(x, u, want), sy_nsrc_ge(x, u, n)), rest)
```

**WHY `rest` IS A `Bool` VALUE AND NOT A CLOSURE IS THE POINT.** BEND HAS NO
HIGHER-ORDER FUNCTIONS, SO A CLOSURE IS NOT AN OPTION -- **BUT THE ORIGINAL CODE ALSO
EVALUATED `REST` EAGERLY** (`Bool.and` IS NOT LAZY IN ITS ARGUMENTS), **SO PASSING THE
VALUE PRESERVES THE EVALUATION ORDER EXACTLY**. `sym_82.pat`'s `all_invalid.go(...)` RAN
BEFORE THE `Bool.and` AND IT STILL DOES.

**THE TWO PREDICATES ARE NOT MERGED INTO ONE HELPER**: `sy_nsrc_is` AND `sy_nsrc_ge` ARE
`==` AND `>=`, AND ONE OF THEM WOULD HAVE TO GROW A FLAG.

**THE BIGGEST SINGLE COLLAPSE**: `sym_462.pat` WENT **9 LINES -> 6** AND `sym_174.pat`
WENT **11 LINES -> 1**.

### LEVER 1 -- "MOVE THE ROWS TO `gates/`" -- **DOES NOT APPLY, AND HERE IS WHY**
