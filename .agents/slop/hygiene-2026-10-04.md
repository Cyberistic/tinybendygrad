## 2. THE GLOB-SOUNDNESS PROOF

The brief's claim — "`tree-verdict.py` globs `*.bend`, so every 'ALL PROOFS CHECK' claim was a
claim about a glob" — is **false for that tool**, and true for the census method.

`tree-verdict.py` `bend_files()` (position 86-93) uses **`os.walk` + `f.endswith(".bend")`**,
not `glob`. `os.walk` descends into dot-directories and `endswith` matches dot-names, so the
harness sees everything. The file's own comment (position 55-60) says exactly this: "A filename
is not evidence, so these never decide a bucket."

The exposure is in the **census**, and it is real. Measured on this tree:

```
root-level glob.glob('*.bend')  ->  []          .bend IS on disk and is NOT matched
fnmatch('.bend', '*.bend')      ->  True        (fnmatch is not the issue)
```

Python's `glob` refuses to let `*` consume a leading dot, so a file named `.bend` is invisible to
`glob('*.bend')` while `find -name '*.bend'` sees it. **One file hides from that glob: root
`.bend`.** Any harness that discovers `.bend` files by glob rather than by `os.walk`/`git
ls-files` is blind to it. `find` and `os.walk` are both sound here.

**The census has a second, larger hole, in the other direction.** Four `.bend` files exist on
disk under `tinybendygrad/` and are **not tracked**, so they are counted by `find` and absent from
a fresh clone:
