3.1  CALLING CPython.  The smallest thing that IS a backward pass:
       a = Tensor([2.,3.]); b = Tensor([4.,5.]); (a*b).sum().gradient(a,b)
     on DEV=NULL, so it needs NO device, NO Buffer, NO realize.

     forward graph : n=6  ops=['BUFFER', 'COPY', 'MUL', 'REDUCE']
     gradient(a,b) : 2 grads, grad[0] n=7
     ops the BACKWARD graph has that the forward did NOT: ['CAST', 'CONST', 'EXPAND']

     *** THIS IS THE MEASUREMENT THAT SETS THE SCOPE. ***
     A first real backward pass over `mul` needs three ops the forward
     corpus never reaches, and NOTHING ELSE. The forward pass itself needs
     4 ops: BUFFER COPY MUL REDUCE.

THE THREE ORDERED STEPS.  Not implemented -- named.
==============================================================================

STEP 1  --  touches mixin/gradient.bend
   do    : Write `compute_gradient` as a fold.bend-shaped Data table: walk = a List<U32> from O.UOp.toposort reversed, grads = a List<(U32,U32)> association, dispatch = the existing first-wins scan the file already has for its own table.
   proof : ONE row: `t_cg_mul` prints the same n= and src-op sequence as CPython's `(a*b).sum().gradient(a)[0].uop` -- which measured n=7 BUFFER/0 COPY/1 CONST/0 CAST/1 CONST/0 EXPAND/2 MUL/2 on DEV=NULL. A driver that never applies a rule prints n=1 and moves. Because CAST/CONST/EXPAND are the NEW ops, this row is UNSATISFIABLE by a stub that returns the forward graph.

STEP 2  --  touches tinybendygrad/tensor.bend:951
   do    : Replace the `backward`'s zip TODO(p3) with the call into step 1, and wire `Tensor.grad_set` (already a def at :279, currently dead) to it. Also `t.grad.assign(t.grad + g)` needs `assign`'s spine, which is ported (tn_assign_store, :889).
   proof : ONE row: a `tn_backward`-level row that, over a BUFFER->MUL->REDUCE fixture, prints the same scope COUNT and the same grad ROOT OP as CPython. `tn_needgrad=2` already pins the filter half, so the row is the second half and the pair is what makes it falsifiable.

STEP 3  --  touches mixin/elementwise.bend (cast/expand) + graphcmp corpus
   do    : Land CONST/CAST/EXPAND reachability: `tn_cast` already exists in tensor.bend:463-494 but is DEAD (measured, stage 2), and mixin/elementwise.bend owns elementwise's cast/expand. Then add the training graph to the graphcmp corpus.
   proof : ONE row in graphcmp: a `bw` graph whose py side is `compute_gradient` over a hand-built BUFFER/CONST/MUL/REDUCE, run under `sh .agents/slop/graphcmp-run.sh`. AGREE at the field-record level. That is the owner's standing ask -- 'compare graphs properly with tinygrad' -- and a backward graph is the fixture it has never had.

WHY THIS ORDER. Step 1 is the whole capability: it is the only piece
with no port file behind it at all. Step 2 is 12 lines in a file that
already has the scope filter and the assign spine. Step 3 is reachability
and corpus, which is what makes the first two COMPARABLE -- and it is
last because a backward graph that disagrees with tinygrad for a
reason that is not the driver's is the failure mode that costs the
most: it looks like a driver bug and sends you into gradient.bend.

WHAT IS DELIBERATELY NOT A STEP: `realize`, `run_linear`, `Buffer`.
Measured above: `compute_gradient` runs to completion on DEV=NULL with
no device state. A first real backward pass is a GRAPH claim, and
tensor.bend:1036 already records realize as a separate wall. Folding
realize into step 1 would make the step untestable, which is the
opposite of the point.
