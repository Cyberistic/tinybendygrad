## 2. WHAT UPSTREAM DOES — **`dtype.py:230`, A PASS-THROUGH, NOT SATURATION**

```python
def float_to_bf16(x):
  if not math.isfinite(x): return x        # dtype.py:230
```

**Upstream returns `x` UNCHANGED.** So the brief's framing — "if upstream's answer
is that non-finite round-trips, then the missing guard is not a bug and the
`isfinite` idea is the defect" — resolves the other way: **non-finite round-trips,
so the missing guard IS the defect, and the `isfinite` idea is exactly right.**
There is no third answer; saturation would be a third answer and is wrong.

Note this is the *same shape* as the fp8 class the brief cites, and the same
shape as the JS fix: **the defect was never "the guard", it was "which side of
the threshold upstream puts the value on".** Here upstream puts non-finite on the
**pass-through** side, and `dtype.bend:608` already had it right — so the two lanes
disagreed in the tree before I started.

## 3. THE FIX, AND IT IS ONE LINE

`dtype.c:193-206`, the guard is a pass-through keyed on the exponent field, which
is `math.isfinite` read on a pattern (`dtype.bend:601` already says this).

### THE GATE THE BRIEF SPECIFIED CANNOT SEE THIS DEFECT, AND THAT IS A THEOREM

> For any pattern whose low 16 bits are **zero** — which is **every** bf16 code,
> since bf16 *is* the top half of an f32 pattern — adding `0x7FFF` **cannot carry
> out of the low half**, so the unguarded rounding line is the **identity** there.

So on all 65,536 of family B's rows, "guard present", "guard absent" and "guard
inverted" are the **same function**. Measured: `PLANT-inverted` and
`DISARM-removed` each move **0** rows over B+N. The defect is real — 16,776,960
patterns — and it is **invisible to the very gate the brief's own remedy would
build**. A gate built to the brief would have gone green on the unfixed tree.

Both facts are needed. Either alone is a false report: "the gate passes" without
the defect is a false all-clear; "the gate passes" *with* the theorem is a gate
that needs a different family.

**What does see it:** family **X** — finite patterns with a **nonzero** low half,
every one of the 512 finite high halves x 12 low halves bracketing every RNE
decision. `PLANT-inverted` moves **5,632** rows there.

## 5. THE NaN CLASS BREAKDOWN — and it is 16.7 MILLION, not 256

A bf16 has 128 non-finite encodings per sign, so 256 total, and **all 256 pass
before and after** — for the carry reason above. The defect lives in the f32
non-finite space, which is **16,777,216** patterns, and the census splits it:

| class | patterns | wrong before | wrong after |
|---|---|---|---|
| **+inf / −inf** | 2 | **0** | 0 |
| **+NaN / −NaN** | 16,777,214 | **16,776,960** | **0** |
| kept by luck (low half zero) | 256 | — | — |

**Every wrong row is a NaN whose payload is destroyed.** `0x7F800001` →
`0x7F800000`; `0x7FFFFFFF` → `0x80000000`, a NaN becoming **negative zero**.
Inf was never wrong: adding `0x7FFF` to an inf's zero mantissa cannot carry.

**A NaN count averaged over all NaNs is a count with no class breakdown, and the
breakdown is the whole answer — confirmed twice here.** Averaged, this reads
"99.998% of bf16 non-finite values are fine". By class it is: **both infinities
correct, every NaN payload at risk.** The class split is also what proves the
guard is a *pass-through*: a saturation guard would have broken the 2 infinities
too, and `PLANT-saturated` moves **508** rows confirming the instrument sees that
difference.

## 9. RULES LEARNED

- **`BF16-1` — A gate over the bf16 input space is BLIND to the bf16 defect, and
  it is blind by THEOREM, not by sampling.** bf16 is the top half of an f32, so
  every bf16 code has a zero low half and `+0x7FFF` cannot carry out of it. The
  unguarded and guarded lines are the same function on all 65,536 codes. **A green
  gate here is not weak evidence, it is evidence of nothing** — and the fix is not
  "add more rows", it is "add a family with a nonzero low half".
- **`BF16-2` — "UPSTREAM'S Bf16 IS NOT CORRECTLY ROUNDED" is true and it cost two
  wrong models to learn.** `dtype.py:232` is a bit add, so a small f32 subnormal
  carries a whole binade. Any model that implements correct rounding will
  disagree with upstream on **16,711,680** finite patterns and be wrong, not the
  port. **Before modelling a bit trick, check whether upstream is doing the trick
  or doing the maths** — and measure the model's disagreement count against
  CPython before believing it.
- **`BF16-3` — An instrument must be shown able to report the RIGHT answer.** The
  JS control reported 8,388,606 rather than 0, which is correct and was
  indistinguishable from a broken comparison until the plant was run too. A sweep
  that only ever prints "many" is untested.
- **`BF16-4` — A guard is necessary and not sufficient.** C: the guard makes
  16,777,216 non-finite patterns exact. JS: the guard leaves 8,388,606 sNaNs
  wrong, because the quieting is in the runtime. **A pass-through guard on a NaN
  is only as good as the boundary that carries the NaN.**
- **`BF16-5` — `of32` returns an f32 VALUE, not a pattern.** Comparing a JS
  seam's return against an expected bit pattern reports 2.1 billion false
  disagreements on a correct file. **Read the value's bits back** (`Float32Array`
  + `Int32Array` view). The C seam returns the pattern, so the two lanes' return
  conventions differ and a shared driver that assumes either is wrong for one.
