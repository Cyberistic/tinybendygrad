# 1. THE TWO MECHANISMS
# ---------------------------------------------------------------------------
# BUG 1 -- `dd_rs.add` appended unconditionally, so a node with two parents was
#   listed once per PARENT. `seen` is prepend-built, so one prepend per POP and
#   a shared node is popped twice. CPython's `cone` (dd-oracle.py:179-191) dedups
#   by `id(v)` and lists it once.
#   FIX  `dd_rs.add` takes the freshness `Bool` as a PARAMETER and prepends only
#        when fresh. The Bool must be a parameter: a `match` may not scrutinise a
#        computed value or a local binder.
#
# BUG 2 -- `dd_rs.push` prepended left-to-right, so the pop order was src[n]
#   first. `dd_rs.cat(h, st) = h <> st` is a PREPEND, and composing it as
#   `push(q, t, cat(s, st))` walks src[n] -> src[0].
#   FIX  `push(q, t, cat(s, st))` -> `cat(s, push(q, t, st))`, so the stack is
#        built in the order it is popped: src[0] first, which is what
#        dd-oracle.py's `cone` does (`for s in v.src: go(s)`).
#
