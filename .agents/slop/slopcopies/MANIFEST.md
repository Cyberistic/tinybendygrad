## WHAT A FULL-PATH CITATION INDEX MISSES
The first pass matched full repo paths only, and the brief's own measurement is why that is not enough: **a report writes `differverdict/VERDICT.md`, not `.agents/slop/differverdict/VERDICT.md`** -- and `checks/differ.py:160` does exactly that. So each candidate is matched three ways: the full path, the path relative to `.agents/slop/` (`abi/abi_gate.py`), and -- only for the 4 candidates directly in `.agents/slop/`, where the second form does not exist -- the bare basename. The bare basename is NOT treated as a citation (trap 1: `bend` had 89 citers); those hits are adjudicated individually below.

The trailing guard is `(?<!\w)(?!\.\w)`, not `(?!\w.-])`. MEASURED: a path at the end of a sentence is followed by the sentence's full stop, and a guard that eats the full stop scores **0 tokens** for `generated by .agents/slop/w64/gen.sh. Do not hand-edit.` The first guard run dropped that citation; it was found by diffing SUBSTRING counts against TOKEN counts, and after the fix the two agree exactly (**0 divergent pairs**), which is the closure property that says the index is complete.

## THE DETECTOR MISSED ONE, AND THE BELT DID NOT CATCH IT
`checks/gen.sh:45` writes a banner naming the driver that wrote it: `# W-2 candidate k=$1 -- generated by .agents/slop/w64/gen.sh.` **That citation was scored as NO citation.** The token class ended in `[A-Za-z0-9_.-]*`, so the tokenizer ate the sentence's full stop and emitted `.agents/slop/w64/gen.sh.` -- with the stop -- which equals no candidate. The trailing guard `(?![.\w])` could not help: by then the stop was already inside the token.

It was found by **re-running the index after the deletion with the class corrected to `[A-Za-z0-9_]`**, which left exactly one residual. The substring belt did not find it, and the reason is worth stating because it is the whole lesson: **the belt used a *different* regex and compared its own substring count against its own token count.** Both numbers were right and the answer was still wrong, because neither method ever looked at `pass3.py`. **A belt that re-runs the same method is a second opinion from the same mind; a belt needs two methods that do not share a regex.**

## UNSETTLED -- REPORTED, NOT FIXED
Each of these is a real defect, measured, and **none of them is this pass's to fix.** Touching a gate's contract, a live unit's tree, or a generator's output name from a cleanup is how the previous pass of this class broke 23 citations.

1. **`.agents/slop/helpers-tc-gate.sh:29,34,56,58` still write `$GT.py`.** `REVIVE.md:217`, `.agents/TODO.md:320` and `notes/bend2-constraints.md:24437` all record that the driver "now writes `$GT.rows`" and that it was re-run. **The rename reached the artefact and the reports and never reached the driver.** So the file being deleted here is the driver's *output*, and the driver recreates it on the next run -- deletion is safe, and the report is wrong. Whether the driver or the reports should move is the `revive` unit's call, not a cleanup's.

2. **`checks/abi4_gate.py:76` sets `REPO = HERE.parents[2]`, which is TWO LEVELS ABOVE the repository root**, so `:81 JS_LANE` resolves to `/Users/cyberistic/src/tinybendygrad/runtime/dtype.js` and `:306` raises `FileNotFoundError` before it ever reaches `:464`. MEASURED: `checks/abi4_gate.py` exits 1 in 0.08 s with that traceback, **before this pass touched anything**. So the one genuine runtime dependency on a copy -- `rc_of(REPO / ".agents/slop/abi/abi_gate.py")` at `:464` and the same at `:465` -- is in code that cannot currently run. Both are still repointed, because the repointing is correct whether or not the line is reachable; the off-by-two in `REPO` is a separate defect and fixing it would change what a gate does.
