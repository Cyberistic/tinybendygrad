`:309`/`:311` `no_overflow`, and the guard that SUPPRESSED the rule before it narrowed it

`((x op c1) op y) -> (x op y) op c1` carries two guards upstream:

    no_overflow(m:=x op y)                      both ops
    x.dtype in wints or c1.arg == -1            `*` only

BEFORE/AFTER, MEASURED on int8, one arena per case, `.agents/slop/sym92/probe-309.bend`:

    narrow (x,y in [0,10])            wide (x,y in [-128,127])
    ---------------------------------------------------------
    no guard:   (add (add x y) c1)    (add (add x y) c1)     <- wide folds a sum that CANNOT fit
    guarded:    (add (add x y) c1)    (add (add x c1) y)     <- narrow folds, wide refused

The `wide` row is the defect: `x+y` ranges over [-256, 254] and int8 holds [-128, 127], so CPython
declines and an unguarded port rewrote it anyway.

**THE FIRST VERSION OF THIS GUARD SUPPRESSED THE RULE ENTIRELY**, and the probe said so in the same
two lines: both rows came back `(add (add x c1) y)`, including the narrow one that must fold. Cause:
`no_ov` read the bounds off the CALLER's fold, and the node the guard is about did not exist when
that fold was built, so `vmin`/`vmax` answered `None`, `ovm` answered `False`, and every firing was
refused. **A guard whose precondition is always false is not a narrow rule, it is a deleted one**,
and it typechecks. The fix is one line -- rebuild the table from the arena the node was minted INTO
(`sym_280.bt(F.folded(O.Found.ar(f)))`) -- and the difference is visible only in the narrow row.

THE PAIR IS THE INSTRUMENT. A guard needs a case that must still fire; a probe that only shows the
refusal cannot tell a narrow rule from a dead one, which is this tree's `DEAD IS NOT A ZERO` in the
small.
