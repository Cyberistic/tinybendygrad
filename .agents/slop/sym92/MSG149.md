**AND THE TRUTH IS 3.** MEASURED against `gates/symrules-census.py`'s AST walk of the SAME upstream at
the SAME pin: `sym` is 133 rules. The port's `sym_table` holds 130, so `skip` is 3 -- and the census's
three MISSING rows are EXACTLY those three: `symbolic.py:450` and `:451` (`pm_simplify_valid`, two
rows) and `divandmod.py:103` (one row).

**130 + 3 = 133 = upstream `sym`, SO THE PORT IS SHORT EXACTLY THE THREE RULES THE CENSUS NAMES AND
NOTHING ELSE.** That is the statement this row was SUPPOSED to make, and it could not make it while
carrying a hand copy of the count from an old pin: the file held `139`, which was
`14+48+9+1+46+3+1+2+14+1` -- the decomposition at the PREVIOUS pin, before the re-vendor moved
every count in it.

THE CENSUS AND THE PORT NOW AGREE EXACTLY, and that is a cross-check neither had before: the census
counts upstream's rules from the AST and the port counts its own rows from the table, and the
difference is 3 in both directions.
