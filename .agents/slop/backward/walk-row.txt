# ------------------------------------------------------------------------------
# THE HEADLINE ROW, spelled out
# ------------------------------------------------------------------------------
#   walk_row=MUL/2 ADD/2 ADD/2 | grads_n=6
#
# Its two halves ARE two of the oracle's own lines, transcribed BY SCRIPT from
# `oracle-cg.txt` (`oracle_dag_walk` and `oracle_dag_grads_n`) and not by hand:
#
#   oracle_dag_walk    = MUL/2 ADD/2 ADD/2      <- the walk's SIGNATURE, op/nsrc per node
#   oracle_dag_grads_n = 6                      <- the COUNT of gradients produced
#
# A signature and a count in one value, because a count alone is what this project's own
# traps punish: `device.bend` shipped `sig=0 4 5` while calling CPython's `0 4 8` "a
# variation", and every mutation left it green. And the COUNT cannot be produced by a
# wrong walk here, because CPython's own forward-order counterfactual
# (`oracle_fwdwalk_n`, unreachable -- see the DENOMINATOR) leaves almost nothing, and the
# three signature tokens are the only three nodes a REVERSE walk can reach from a root
# with two children.
#
# ------------------------------------------------------------------------------
# WHAT IS NOT GATED, STATED
# ------------------------------------------------------------------------------
# 1. THE `srcs=` MULTISET of each `osig`, i.e. the sorted op/nsrc list over the whole
#    gradient tree.  The oracle sorts it ALPHABETICALLY and `O.Ops.value` is DECLARATION
#    order (`BUFFER` is 2, `ADD` is late), so it is not a substitute; reproducing it needs
#    an alphabetical rank for all sixty ops.  `walk_grad_*` therefore pins the COUNT and
#    the ROOT, and those two are what separate all four cases:
#      walk_grad_a=5 root=ADD/2   the ACCUMULATE (gradient.py:138) -- a fresh insert
#                                 would answer MUL/2
#      walk_grad_b=4 root=MUL/2   a FRESH INSERT (gradient.py:139)
#      walk_grad_c/p/q/r=2 root=CAST/1   the SEED verbatim (gradient.py:118)
# 2. THE EXPAND FIXTURE, which is the one that would exercise gradient.py:130's HOLE and
#    gradient.py:120's SKIP for real.  `walk_hole_n=0` and `walk_skip_n=0` are TRUE FOR
#    THIS FIXTURE and are not a coverage claim about the other: CPython cannot compute the
#    second fixture at all (RuntimeError above).
# 3. THE SHAPED-EDGE REDUCE (gradient.py:132-133).  Every node in this fixture is a
#    SCALAR, so upstream's guard `k._shape is not None and v._shape is not None and
#    k._shape != v._shape` is false throughout and the port omits the branch.  It is not
#    merely deferred: it is the line CPython raises on.
# 4. THE BACKWARD-METADATA PASS (gradient.py:140-144).  It reads `all_metadata` and has no
#    effect on `grads`, so no row here can see it.
# 5. `call_gradient` is unreachable from this walk; a CALL node reaches gradient.py:127's
