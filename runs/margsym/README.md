# runs/margsym -- the symbolic-dim unit's evidence, 2026-10-04

Everything here was produced by the unit that closed `fold.bend`'s `ssimplify` wall. The
two things a reader needs are (1) the fix's own row set and (2) the proof that the wall
was TWO defects. Both are here, and every command is re-runnable.

## THE SUBSTRATE IS NOT SAFE TO TRUST WHILE ANOTHER UNIT OWNS ops.bend

`uop/ops.bend` went COLD TWICE during this unit, both times under its owner, and both
times the failure looked exactly like this unit's own regression:

    snap-vs-live.sh      print the pinned snapshot's md5 for every file in fold.bend's
                         import cone, BESIDE the live one. A `** DIFFERS **` here is the
                         first thing to read when a bend run prints nothing.
    snap/                `rsync -a --delete tinybendygrad/ snap/tinybendygrad/` -- a WHOLE
                         tree, because the relative imports resolve inside it and a
                         `$TMPDIR` scratch copy cannot resolve one. `fold-mut.py` takes
                         FOLD_ROOT / FOLD_SRC and runs against this.

MEASURED: at 12:0x `ops.bend` was 7813 lines with `vrn_lo` reading `r.lo`, a projection
that does not exist; and at 13:0x `vv_of`'s `Quant` was not a `Data`. Both made every lane
in this directory print zero rows, and the second made `fold-mut.py` report all sixteen
mutations as `CHECK FAILS in both lanes` -- which reads exactly like sixteen blind spots.

## THE TWO LANES, AND WHY A SNAPSHOT

`fold.bend`'s own gate is `diff <(grep '^mv_' py) <(grep '^mv_' bend)` and the mutation
table is `oracles/fold-mut.py`, run with `FOLD_ROOT`/`FOLD_SRC` pointing at
`snap/`. `runs/graphcmp/D` is regenerated by `sh .agents/slop/graphcmp-run.sh` and was
GREEN on this unit's last run against a GOOD `ops.bend`: 16 graphs, 14 AGREE, `sym` one of
them, 14 of 16 byte-identical, selfcheck OK, 5 of 5 stability pairs.
