# gates/

Every gate is Python. The shell form is retired, and the reason is in this repo's own
history rather than in taste.

## WHY NOT `.sh`

A shell gate failed here four different ways, and three of them are recorded in
`d2cde2f2c` ("gate harnesses: four of them LIED, and every fix has been seen red"):

| shape | failure |
|---|---|
| `diff A B && echo MATCHES` | under `set -e` a failing `diff` inside an `&&` list does **not** fire errexit — the script exits 0 having printed a diff |
| `trap 'rm -rf "$OUT"' EXIT` | the trap's last command status becomes the script's, so a successful `rm` turns an earlier failure into exit 0 |
| `<( ... )` | a bashism: under `sh` the script does not parse at all, and a gate that cannot parse is a gate nobody reads |
| `${=SUB}` | zsh-only: under `sh` the array never expands, the loop never runs, and a hash guard compares `""` to `""` and reports UNCHANGED |

None of those can happen in Python. The two policies a shell form made awkward — a **missing
BASELINE** and a **stale DIVERGES list** — are explicit constructor arguments in `gatekit.Gate`.

## THE SHARED HALF, AND WHY IT IS SHARED

`gatekit.py` holds the plumbing that is identical in every gate — the warm check, the three
lanes, the row counts, the diff — and **nothing else**. A gate file holds only what differs:
its rows, its divergences, and what each divergence's content is pinned to. `gatekit` knows
nothing about any particular gate, so a bug in it cannot be a bug in a claim.

## WHAT A GATE MAY ASSERT, and all four shapes are in use

1. **plain rows** — `wk-f32-gate` (18), `ew-consts-gate` (21)
2. **a divergence, pinned on BOTH sides** — `wk-cd-gate`'s `cd_none`: the oracle says
   `i64`, the port says nothing, and a divergence nobody checks is a tolerance
3. **a port-only row** — present in both port lanes and **absent from the oracle**, because
   the oracle deliberately omits it. The absence is asserted too: a gate that only checked
   the row would pass the moment the oracle grew it, and the exclusion would then be hiding
   a real comparison
4. **an order-only divergence** — the tokens are equal and the order is not, so the row is
   compared as a multiset and **both sides' orders are asserted**, which makes a change in
   either toposort a gate failure rather than something the canonicalisation absorbs

## HOW THEY ARE RUN

This section used not to exist, and its absence is why `gates/README.md` spent its header on why
gates are Python and never answered the only question a reader has: **who invokes them.** MEASURED
2026-10-16T15:55Z, **walking `checks/` rather than naming paths in it**: **`checks/gatesweep.py` is
the one instrument under `checks/` that names a gate, and it sweeps every `gates/*-gate.py` by
directory walk**; `gates/runner.py` delegates to it by pinned `sha256`. MEASURED over the ten
automated surfaces (`.github/workflows/*.yml` and `.pre-commit-config.yaml`), **0** invoke a gate or
a `checks/` instrument — so *nothing that runs automatically runs a gate*, and **no CI-verdict claim
can be made**.

**A RUNNER ALREADY EXISTED AND AN EARLIER REVISION OF THIS FILE SAID IT DID NOT.** The "numerator 0"
reading came from naming three paths — `bin/`, `checks/e2e.sh`, `checks/differ.py` — instead of
walking `checks/`, so it was right by accident and its denominator was already wrong.
`gates/docnum-claim-gate.py` HOLDS THE COMPARISON AND IS WHAT CAUGHT IT; `AGENTS.md` RECORDS
`checks/gatesweep.py` FIVE TIMES AND THIS SECTION READ IT WRONG FOR ONE DAY.

### RUN ONE

    .venv/bin/python gates/wk-cd-gate.py       # exits 0 on agreement, 1 on any disagreement
    .venv/bin/python gates/wk-f32-gate.py

Each writes its lanes to `gates/artifacts/<name>/` — **not** into `.agents/slop/`, which is
being pruned. Artifacts are regenerated by every run and are outputs, never inputs.

### RUN THE SET

    .venv/bin/python gates/runner.py --plan    # the set, the derivations, the projection. Runs NOTHING.
    .venv/bin/python gates/runner.py --plant   # the five refusals, on synthetic state. No `bend`.
    .venv/bin/python gates/runner.py           # the DEFAULT: a BUDGETED prefix, 300 s
    .venv/bin/python gates/runner.py --all     # every gate in the set

**`runner.py` does not sweep, it PRECONDITIONS.** The loop is `checks/gatesweep.py`'s — MEASURED
2026-10-15 at `PASS=66 FAIL=2 SKIP=2 DEAD=0` over 70 gates in 616.0 s — and it is loaded by path,
pinned by `runner.py`'s `DELEGATED` shas, and never re-spelled. What `runner.py` adds is the reason
a sweep is dangerous rather than slow: **it starts**, and nothing stood between the operator and an
hour of `bend` at 1–2 GiB a piece.

### THE FIVE REFUSALS. All exit 3, all print `REFUSED, NOT A VERDICT`

| precondition | fired by | live measurement |
|---|---|---|
| `PIN-DRIFT` | `gatekit.oracle_drift(DELEGATED)` — the three files `runner.py` delegates to moved | `checks/gatesweep.py` sha mismatch |
| `NO-POPULATION` | an empty derivation, or a `Gate`-constructing gate outside the run set | the empty-tree plant |

the repeats present in it):

| `i64-shl-gate` | 3.4 | 383–390 | 1.00× · +2% |
| `wk-f32-gate` | 4.0–5.2 | 495–532 | 1.30× · +7% |

| `decomp_graph_census-gate` | 35.9–36.8 | 740–1024 | 1.03× · **+38%** |

Three runs of the ten gave **`PASS=8 FAIL=2` every time** — the verdicts are stable — and
**113.1 s / 113.0 s / 110.5 s wall**. Projected over the run set: **788–913 s (13.1–15.2 min)**.

**THE MEASUREMENT NOISE IS PART OF THE ANSWER.** `decomp_graph_census-gate`'s peak moved **740 →
1024 MB (+38%)** and `indexread-gate`'s runtime moved **1.8 → 3.5 s (1.94×)** on the SAME command
against the SAME tree, with `loadavg` 8.4–13.7 on 12 cores throughout — the same 2.02× spread
`AGENTS.md` records for this file. So a single sample prices a sweep to about ±15%, and
**`onnx_census-gate` peaks at 1839 MB against the default 2048 MB ceiling — 10% of headroom.** A
ceiling that a gate can reach is not a ceiling; a concurrent sweep would be a KILLED-ON-MEMORY, and
a gate killed on memory is a `SKIP`, not a failure, which is the whole reason the token is read.

**A runner whose usefulness arrives after fourteen minutes is not a gate, it is a bill.** So the
default is **a budget, not a subset**: gates start in the discovered order and the sweep stops when
`--budget-seconds` (default 300) is spent, printing how many did not run and exiting `SKIP` (4).
Nothing in `runner.py` names a gate — a subset named in this file would be the eighth instrument in
this tree to hold a population it wrote down, and wrong the day a gate is renamed.

**`--measure-only` IS NOT AN OVERRIDE, IT IS A LOWER CLAIM.** It runs under unsatisfied
preconditions, stamps every run `MEASUREMENT`, prints which preconditions it ran under, and exits
`SKIP` (4) whatever the gates said. A mode that runs under a broken precondition and exits 0 is the
exact defect `gatekit` gained exit 5 to stop.

**THE 2 FAILS ARE ONE DEFECT AND IT IS NOT A GATE FAULT.** `indexread-gate` and `pins-shape-gate`
are the pair `.agents/TOOLS.md` already records: `pins-shape-gate.py: ls-files` is
`indexread-gate`'s new offender, because `indexread`'s own claim forbids reading the git index. One
gate reads the index while another is judged for reading it.

## DRIVERS AND ORACLES LIVE BESIDE THEIR GATE, IN `gates/`

This section used to say the opposite, and the opposite is what happened: a sweep of
`.agents/slop/` deleted **7 of the 9** driver/oracle files this directory's gates named, and
every gate that named one went red on `no such file` while its source still said the path was
fine. A gate's own required input was deletable while the gate continued to name it. That is the
same failure `checks/e2e.py` records for its two missing inputs, and it is not a property of
those particular files.

So a gate's `.bend` driver and its CPython oracle sit in `gates/`, named by the gate that needs
them. `gatekit` resolves `gates/` first and the repo root second, so a driver may still be shared
by path. Two gates that must agree byte-for-byte (the frozen shell oracles `mixin-op` and
`beautiful-mnist` diff against) keep their `sha256` pin **and** live in `gates/`: a pin you
cannot find the file for is not a pin.

The corpus argument for slop does not survive contact with a pruning directory. What matters is
that a gate's inputs are as hard to delete as the gate.

## THE META-INSTRUMENTS, AND THE ONE POPULATION THEY SHARE

Three files here are not gates over a subject; they are gates over the gates.

| file | what it enumerates | how |
|---|---|---|
| `gates/gates-pop.py` | every gate in the tree | AST `__main__` for Python, self-dispatch for shell, `--ledger` diffs the previous run |
| `gates/retention-check.py` | what a generated directory may hold | the generator's own `declared()` and `unhealthy()`, never a second opinion |
| **`gates/gendirs.py`** | **every directory something WRITES INTO** | **a scan of every write site in the tree** |

`gendirs.py` exists because `checks/gen/` was invisible to both of the others.
`gates-pop.py` enumerates **gates** and `retention-check.py` enumerates **two registered output
families**, and `checks/gen/` — written by `checks/abi_gate.py:616` through `bend -o` — is
neither a gate nor a registered family. **A POPULATION DEFINED BY A THREE-ITEM LIST CANNOT BE
WRONG ABOUT A FOURTH ITEM BECAUSE IT NEVER LOOKS AT ONE.**

All three import `gendirs.py` **by path**, and all three print its count, so the population has
one implementation and two consumers and the pair can be checked against each other. Measured
2026-10-06: `retention-check.py` clause V and `gates-pop.py` clause IV both print **194**.

    .venv/bin/python gates/gendirs.py            # the table: every written-into directory
    .venv/bin/python gates/gendirs.py --plant    # seven plants, synthetic trees only

`gendirs.py`'s population is a **lower bound** and says so on every run: `checks/abi4_gate.py:501`
reaches `checks/gen/` through a `subprocess.run` that names no output path at all, so the writer is
named by a *call* and the target by a *convention inside another program*. Closing that needs
execution, and nothing here executes a gate. `.agents/slop/gendirs/` holds the table, the
property evaluation, and the seven plants' reasoning.

## CLAUSE IV: WHICH GENERATED DIRECTORIES CAN REPORT HEALTH

Clause IV asks one question per output family: *does it carry a zero-argument `healthy` callable?*
(`retention-check.py:520-525`). A family with `healthy=None` prints `UNMEASURABLE` and **`continue`s
without touching `red`** (`:524`) — so it is **reported and NOT charged to rc**. The leniency is
clause IV's alone: clause I's residue is red at `:435`, clause II's `UNMEASURED`/`MISSING`/`FALSE` at
`:410`.

| family | dirs | `healthy` | why |
|---|---|---|---|
| `runs/graphcmp/D/` | 1 | `differ.unhealthy() + differ.artefacts_ok()` | the run PERSISTS its verdict: `D0-run-summary.txt` is `name=value` rows incl. `census-rc=rc=0` |
| `gates/artifacts/<gate>/` | one per gate | `None` | `gatekit`'s verdict is an **exit status** — printed, never written |

The gate dirs are **discovered, not listed**: `Output.dirs()` (`:99-110`) walks `gates/artifacts/`
with `iterdir`; `0/N dirs` is `len(dirs)`.

**What a gate leaves on disk is lanes, not a verdict.** A green run promotes exactly seven fixed
names — `py.rows`, `bd.out`, `bn.out`, `py.cmp`, `bd.cmp`, `bn.cmp`, `gate.bin` — through `_settle`
(`gatekit.py:436-449`). The verdicts are the five exits (`gatekit.py:59`:
`PASS, FAIL, REFUSED, SKIP, DEAD = 0,1,3,4,5`). Lanes cannot say whether their run was healthy, so
`UNMEASURABLE` is the truthful token.

**What would make them report:** `gatekit` would have to *persist* its verdict — one declared file
per `Gate` dir, added to `GATEKIT_OUTPUT`, paired with a `healthy()` that reads it. That is
`gatekit.py`'s change, not this file's, and it would cover **every** dir under `gates/artifacts/`
(all are written by a `gatekit` `Gate`). Until then, forcing a verdict here would invent a health
rule and widen what counts as healthy.

**`GATEKIT_OUTPUT` is DERIVED from the generator, not transcribed beside it.** `gatekit` publishes
no `declared()`, so this set is the one this file owns — built from gatekit's OWN lane constants
(`LANE_ROWS`/`LANE_OUT`/`LANE_CMP`, `gatekit.py:68-70`) plus the one `gate.bin` literal
(`gatekit.py:317`), imported at `retention-check.py:68`. The transcription this replaced named
`*.txt`/`*.sub`, which gatekit had stopped writing: clause I then named the ENTIRE contents of all
11 gate dirs residue. MEASURED before/after: `11 with residue / 66 files` → `12/12 dirs clean`.
