# gates/

Every gate is Python. The shell form is retired, and the reason is in this repo's own
history rather than in taste.

## WHY NOT `.sh`

A shell gate failed here four different ways, and three of them are recorded in
`d2cde2f2c` ("gate harnesses: four of them LIED, and every fix has been seen red"):

| shape | failure |
|---|---|
| `diff A B && echo MATCHES` | under `set -e` a failing `diff` inside an `&&` list does **not** fire errexit — the script exits 0 having printed a diff |
| `trap 'rm -rf "$OUT"' EXIT` | the trap's last command status becomes the script's, so a successful `rm` turns an earlier failure into exit 0 |
| `<( ... )` | a bashism: under `sh` the script does not parse at all, and a gate that cannot parse is a gate nobody reads |
| `${=SUB}` | zsh-only: under `sh` the array never expands, the loop never runs, and a hash guard compares `""` to `""` and reports UNCHANGED |

None of those can happen in Python. The two policies a shell form made awkward — a **missing
BASELINE** and a **stale DIVERGES list** — are explicit constructor arguments in `gatekit.Gate`.

## THE SHARED HALF, AND WHY IT IS SHARED

`gatekit.py` holds the plumbing that is identical in every gate — the warm check, the three
lanes, the row counts, the diff — and **nothing else**. A gate file holds only what differs:
its rows, its divergences, and what each divergence's content is pinned to. `gatekit` knows
nothing about any particular gate, so a bug in it cannot be a bug in a claim.

## WHAT A GATE MAY ASSERT, and all four shapes are in use

1. **plain rows** — `wk-f32-gate` (18), `ew-consts-gate` (21)
2. **a divergence, pinned on BOTH sides** — `wk-cd-gate`'s `cd_none`: the oracle says
   `i64`, the port says nothing, and a divergence nobody checks is a tolerance
3. **a port-only row** — present in both port lanes and **absent from the oracle**, because
   the oracle deliberately omits it. The absence is asserted too: a gate that only checked
   the row would pass the moment the oracle grew it, and the exclusion would then be hiding
   a real comparison
4. **an order-only divergence** — the tokens are equal and the order is not, so the row is
   compared as a multiset and **both sides' orders are asserted**, which makes a change in
   either toposort a gate failure rather than something the canonicalisation absorbs

## RUNNING ONE

    .venv/bin/python gates/wk-cd-gate.py       # exits 0 on agreement, 1 on any disagreement
    .venv/bin/python gates/wk-f32-gate.py

Each writes its lanes to `gates/artifacts/<name>/` — **not** into `.agents/slop/`, which is
being pruned. Artifacts are regenerated by every run and are outputs, never inputs.

## DRIVERS AND ORACLES LIVE BESIDE THEIR GATE, IN `gates/`

This section used to say the opposite, and the opposite is what happened: a sweep of
`.agents/slop/` deleted **7 of the 9** driver/oracle files this directory's gates named, and
every gate that named one went red on `no such file` while its source still said the path was
fine. A gate's own required input was deletable while the gate continued to name it. That is the
same failure `checks/e2e.py` records for its two missing inputs, and it is not a property of
those particular files.

So a gate's `.bend` driver and its CPython oracle sit in `gates/`, named by the gate that needs
them. `gatekit` resolves `gates/` first and the repo root second, so a driver may still be shared
by path. Two gates that must agree byte-for-byte (the frozen shell oracles `mixin-op` and
`beautiful-mnist` diff against) keep their `sha256` pin **and** live in `gates/`: a pin you
cannot find the file for is not a pin.

The corpus argument for slop does not survive contact with a pruning directory. What matters is
that a gate's inputs are as hard to delete as the gate.
